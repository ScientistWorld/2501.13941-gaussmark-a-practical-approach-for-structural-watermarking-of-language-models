# Overview

- **Paper ID:** 2501.13941
- **Title:** GaussMark: A Practical Approach for Structural Watermarking of Language Models
- **Domain:** NLP / LLM Watermarking
- **TL;DR:** Embeds a detectable watermark into LLM outputs by adding small Gaussian noise to model weights during generation. Detection uses a gradient-based statistical test with formal guarantees and zero generation overhead.

## Short Summary

GaussMark watermarks LLM outputs by adding a small amount of Gaussian noise to the weights of a single MLP layer during generation. The watermark key (a random Gaussian vector) is sampled per deployment of the marked model. Detection works by computing a dot product between the watermark key and the gradient of the log-likelihood with respect to the original weights. Under the null hypothesis (unwatermarked text), this test statistic follows a standard normal distribution exactly, giving rigorous false-positive control. Detection is fast (<1s for 1K tokens) and generation has zero overhead since the only change is a weight perturbation before standard inference. Extensive experiments on Mistral-7B, Llama3.1-8B, and Phi3.5-Mini show high detection rates (~95% for Llama at 200 tokens, FPR=5%) with no significant quality degradation on SuperGLUE, GSM-8K, or AlpacaEval benchmarks.

## Key Results

- **Detection**: At 200 generated tokens, detection rates are ~62% (Mistral), ~95% (Llama), ~65% (Phi3.5-Mini) at FPR=5%. Rates increase with longer sequences.
- **Quality**: No significant degradation on SuperGLUE (avg ~0.70), GSM-8K, or AlpacaEval-2.0 compared to unwatermarked baselines.
- **Speed**: Zero generation latency overhead. Detection in <1s for 1K tokens.
- **Robustness**: Retains nontrivial detection after 10-50% token-level corruptions and roundtrip translation attacks.

## This gym

- Scored on Mistral-7B-Instruct-v0.3 only, 200-token generations, two experiments: clean detection with a
  cross-entropy quality budget, and detection after 20% token-level corruption.
- The evaluator runs each method's `make_watermark`/`detect` on hidden prompts, keys and null texts

# Problem Definition

## Research Question

How can a language-model provider embed a signal into the text its model
generates, so that the provider, holding a secret key, can later test whether a
given text came from its model — with a **statistically valid** false-positive
guarantee, **without degrading the model**, without slowing generation, and
with some **robustness** to edits of the text?

This is the LLM watermarking problem, posed as hypothesis testing:

- **H0**: the candidate text is independent of the secret key (human text,
  another model's text, the provider's own unmarked text, or text marked under
  a *different* key).
- **H_A**: the text was generated by the provider's model marked with this key.

A detector outputs a p-value. It is *valid* when, under H0, `P(p < a) <= a`
for every level `a`; detections are then reported at the nominal levels
`p < 0.05` and `p < 0.01`.

## Setting (fixed)

- Model: `mistralai/Mistral-7B-Instruct-v0.3`, bf16, unchanged architecture.
- Prompts: C4 `realnewslike` documents truncated to `<s>` + 200 tokens.
- Generation: done by the evaluator, temperature 1.0, top-p 0.9, exactly 200
  new tokens (special tokens disabled), one sample per prompt.
- Keys: the evaluator draws integer key seeds. Every 50 prompts share one key
  (one marked deployment of the model per key).

## What a method provides

A method is a directory `checkpoints/watermarkers/<method_name>/` containing
`watermarker.py` (plus any files it reads, e.g. a `config.json`) with two
functions:

```python
def make_watermark(model, key_seed: int) -> dict[str, torch.Tensor]:
    """Return {parameter_name: additive_delta} for the deployment with this key.
    Names are from model.named_parameters(); shapes must match; values finite.
    The evaluator adds the deltas, generates, measures quality, and removes them.
    Must not modify `model` itself."""

def detect(model, key_seed: int, prompts: list[list[int]], texts: list[list[int]]) -> list[float]:
    """Return one p-value in [0, 1] per (prompt token ids, text token ids) for the
    hypothesis 'this text was generated under key_seed'. `model` holds the
    ORIGINAL weights. Must not modify `model` (restore any requires_grad flags)."""
```

The only way to influence generation is the key-dependent parameter change:
the method never sees a prompt at generation time, cannot sample several
candidates, and cannot change the decoding procedure. `detect` receives a
shuffled, unlabeled mixture of marked and null texts; some texts may have been
edited (tokens inserted, deleted or substituted), so their length can differ
from 200.

`method/` holds the reference implementation and `method/export_watermarker.py`
installs it; `baseline/unwatermarked.py` is the no-watermark baseline (installed
by `scripts/baseline.sh`).

## Success Criteria

1. **Valid**: false-positive rates at the nominal levels on texts independent
   of the key — enforced by the evaluator, not traded off.
2. **Powerful**: detect as many marked texts as possible at `p < 0.05` and
   `p < 0.01`; high ROC AUC; small median p-value.
3. **Quality-preserving**: the marked model's cross-entropy on held-out human
   C4 text stays within 1.5% of the original model's, and lower is better.
4. **Robust**: detection survives random token-level edits of 20% of the text.
5. **Key-specific**: text marked under one key must not be detected under
   another.

# Paper's Method

## Key Contribution

GaussMark is a novel **structural watermarking scheme** for LLMs that embeds a watermark by adding Gaussian noise to the model's weights during generation. Unlike token-level watermarking schemes that modify the sampling process, GaussMark modifies the model itself.

The key insight is that small additive perturbations to LLM weights produce models of identical or even improved quality (as observed in model merging and fine-tuning literature). By exploiting this robustness, GaussMark adds just enough noise to create a detectable statistical signal without harming model quality.

## Approach

### GaussMark.Generate (Watermark Embedding)
1. Sample a **watermark key** `xi ~ N(0, sigma^2 * I)` from a multivariate Gaussian distribution
2. Perturb the model weights: `theta_wm = theta + xi` (add the key to the parameters)
3. Generate text using the perturbed model `p_theta_wm`
4. Return: generated text, the watermark key `xi`

Only ONE MLP layer's weights are perturbed. For Mistral-7B: layer 20, `up_proj` weight matrix (58M parameters). The layer is chosen empirically to balance detectability and quality.

### GaussMark.Detect (Watermark Detection)
1. Given: original model `p_theta`, prompt `x`, generated text `y`, watermark key `xi`, variance `sigma`
2. Compute the **test statistic**:
   `psi = <xi, grad_theta log p_theta(y|x)> / (sigma * ||grad_theta log p_theta(y|x)||)`
   where `<,>` is the dot product and `|| ||` is the L2 norm
3. Compute **p-value** = 1 - Phi(psi) where Phi is the standard normal CDF
4. If p-value < alpha (e.g., 0.05), reject the null hypothesis (claim: text is watermarked)

### Key Theoretical Results
- **Statistical Validity (Proposition 3.2)**: Under the null hypothesis H0 (text is NOT watermarked), `psi ~ N(0, 1)` exactly. This means p-values are uniformly distributed and the false-positive rate is exactly controlled.
- **Power Analysis (Proposition 3.4)**: Under a linear softmax model approximation, the test has non-trivial power that increases with model dimension and sequence length.

### Why It Works (Intuition)
- The watermark key `xi` is Gaussian and independent of the generated text under H0
- The gradient `grad_theta log p_theta(y|x)` is also independent of `xi` under H0
- Their dot product, normalized, follows a standard normal distribution
- Under H_A (text IS watermarked), the gradient is correlated with `xi`, making `psi` systematically large

### Practical Implementation
- Perturb only a single MLP layer (not the entire model) to minimize quality impact
- The gradient computation requires only ONE forward pass and ONE backward pass through the watermarked layer
- Generation: NO additional overhead (just weight perturbation, same as regular inference)
- Detection: <1 second for 1K tokens

### Rank-Reduced Variant (Section 4.4)
- Instead of perturbing all directions of a weight matrix, only perturb the **bottom k principal components**
- This allows MORE noise (stronger watermark) while preserving model quality
- Used in some experiments for better quality-watermark tradeoffs

## Reference implementation in this gym

- `method/gaussmark.py` is the evaluator plugin: `make_watermark` returns the
  Gaussian key xi (std sqrt(1e-5)) for `model.layers.20.mlp.up_proj.weight`,
  drawn from the evaluator's key seed; `detect` computes psi with the gradient
  of the summed log-likelihood of the text at the original weights and returns
  1 - Phi(psi). Options in `config.json`: `layer`, `weight`, `variance`,
  `drop_top_pcs` (rank-reduced variant; paper Table 7 uses layer 30 and 1024),
  `min_token_prob`.
- `python3 method/export_watermarker.py --name <name> --config '<json>'`
  installs it under `checkpoints/watermarkers/<name>/`.
- One key per group of 50 prompts (one marked deployment per key), as in the
  paper's per-seed experiments; the evaluator decodes, so generation cost is
  identical to the unmarked model by construction.

# Evaluation

`scripts/evaluate_train.sh` (public slice, `scoring/scores_train.json`) and the
hidden `scripts/evaluate_test.sh` (`scoring/scores_test.json`) run the same
protocol with no arguments on **every** directory under
`checkpoints/watermarkers/`. Both need one CUDA GPU. `scripts/evaluate.sh`
runs the public slice into `scoring/scores.json`.

| slice | documents | keys (50 docs each) | source |
|---|---:|---:|---|
| train (public) | 200 | 4 | C4 realnewslike train shard 00000 |
| test (hidden)  | 400 | 8 | held-out C4 documents, hidden key and sampling seeds |

## Protocol (per method)

1. For each key seed: call `make_watermark`, add the deltas to the model,
   generate one 200-token continuation per prompt of the key's group (the
   per-prompt sampling noise is fixed by the evaluator, so every method sees
   the same random numbers), and measure the cross-entropy of the marked model
   on the group's held-out human documents (prompt + next 200 human tokens).
   Remove the deltas.
2. Detection, with the original weights, on a shuffled unlabeled mixture per
   key:
   - **marked**: the key's own marked texts;
   - **null, unwatermarked**: texts generated by the original model for the
     same prompts (with different sampling noise);
   - **null, human**: the documents' real continuations;
   - **null, wrong key**: the previous key group's marked texts, tested under
     this key;
   - **corrupted marked / corrupted unwatermarked**: the marked and the
     unwatermarked texts with 20% of their tokens edited (random substitutions,
     deletions or insertions of random non-special tokens; one attack type per
     text, balanced).

## Gates (a failed gate scores the run as FAILED)

A failed run receives the worst value of every metric in both experiments
(rates 0, AUC 0, median p-value 1, CE ratio 1.015, false-positive rates 1):

- `watermarker.py` missing, an exception, or more than 3 h per method;
- `make_watermark` returns anything but finite deltas of existing parameters
  with matching shapes;
- `detect` returns the wrong number of values, or any value that is not a
  finite number in [0, 1];
- the method changes the model's weights, buffers, modules or hooks;
- `c4_cross_entropy_ratio > 1.015` (quality budget);
- validity: on any null family (unwatermarked, human, wrong key, corrupted
  unwatermarked; and the pooled first three) the number of texts with
  p < 0.05 or p < 0.01 is significantly above the nominal level
  (one-sided binomial test, p < 0.001). On the hidden slice this is
  >= 36/400 (0.05) or >= 12/400 (0.01) per family and >= 86/1200 or
  >= 25/1200 pooled.

False-positive rates are reported but not ranked: an exact test sits at the
nominal level, and being more conservative than nominal is not better.

## Ranking

The rank sums, over experiments and metrics, weight x |coefficient| x the
improvement over the reference in the metric's better direction, divided by
the metric's spread across the ranked attempts. Only the numbers under each
experiment's `results` in `scoring/scores_test.json` are ranked; the
`_status` block (gates, counts, timings) is informational.
