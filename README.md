# Overview

- **Paper ID:** 2501.13941
- **Title:** GaussMark: A Practical Approach for Structural Watermarking of Language Models
- **Domain:** NLP / LLM Watermarking
- **TL;DR:** Embeds a detectable watermark into LLM outputs by adding small Gaussian noise to model weights during generation. Detection uses a gradient-based statistical test with formal guarantees and zero generation overhead.

## Short Summary

GaussMark watermarks LLM outputs by adding a small amount of Gaussian noise to the weights of a single MLP layer during generation. The watermark key (a random Gaussian vector) is sampled fresh for each generation. Detection works by computing a dot product between the watermark key and the gradient of the log-likelihood with respect to the original weights. Under the null hypothesis (unwatermarked text), this test statistic follows a standard normal distribution exactly, giving rigorous false-positive control. Detection is fast (<1s for 1K tokens) and generation has zero overhead since the only change is a weight perturbation before standard inference. Extensive experiments on Mistral-7B, Llama3.1-8B, and Phi3.5-Mini show high detection rates (~95% for Llama at 200 tokens, FPR=5%) with no significant quality degradation on SuperGLUE, GSM-8K, or AlpacaEval benchmarks.

## Key Results

- **Detection**: At 200 generated tokens, detection rates are ~62% (Mistral), ~95% (Llama), ~65% (Phi3.5-Mini) at FPR=5%. Rates increase with longer sequences.
- **Quality**: No significant degradation on SuperGLUE (avg ~0.70), GSM-8K, or AlpacaEval-2.0 compared to unwatermarked baselines.
- **Speed**: Zero generation latency overhead. Detection in <1s for 1K tokens.
- **Robustness**: Retains nontrivial detection after 10-50% token-level corruptions and roundtrip translation attacks.

# Problem Definition

## Research Question

How can we embed a detectable signal into text generated by a Large Language Model (LLM) so that a model provider with a secret key can reliably determine whether given text was generated by their model, while not degrading text quality, not slowing generation, and maintaining detectability even after common text modifications?

This is the **LLM watermarking problem**: given an LLM, embed an almost imperceptible statistical signal into its outputs that allows authorized detection of machine-generated text.

## Why It Matters

LLMs can now produce human-quality text at scale, raising concerns about:
- Academic plagiarism and cheating detection
- Large-scale disinformation and misinformation
- Attribution of AI-generated content in journalism, law, and policy

Existing watermarking techniques suffer from:
- Increased generation latency (the watermark changes the sampling process)
- Degraded text quality (biased token selection)
- Lack of formal statistical guarantees (high false-positive rates)
- Fragility to text modifications (paraphrasing, editing)

A watermarking scheme is only practical if it has **formal guarantees** on detection reliability, **no impact** on generation speed, **no quality degradation**, and **some robustness** to text corruptions.

## Success Criteria

A successful watermarking scheme should:

1. **Be statistically detectable**: Have a measurable false-positive rate with formal guarantees. When text is not watermarked, the detection procedure should almost never (e.g., <5% of the time) incorrectly claim it is watermarked. When text IS watermarked, detection should reliably identify it.

2. **Not degrade model quality**: Generated text should be indistinguishable from unwatermarked text on standard benchmarks (SuperGLUE, GSM-8K, etc.).

3. **Have zero generation latency overhead**: The watermarking process should not slow down text generation compared to the base model.

4. **Be somewhat robust**: Detection should remain nontrivial even after common text modifications: random insertions, deletions, substitutions, or paraphrasing through translation.

5. **Work with a secret key**: Only someone with the secret key should be able to reliably detect the watermark.

# Paper's Method

## Key Contribution

GaussMark is a novel **structural watermarking scheme** for LLMs that embeds a watermark by adding Gaussian noise to the model's weights during generation. Unlike token-level watermarking schemes that modify the sampling process, GaussMark modifies the model itself.

The key insight is that small additive perturbations to LLM weights produce models of identical or even improved quality (as observed in model merging and fine-tuning literature). By exploiting this robustness, GaussMark adds just enough noise to create a detectable statistical signal without harming model quality.

## Approach

### GaussMark.Generate (Watermark Embedding)
1. Sample a **watermark key** `xi ~ N(0, sigma^2 * I)` from a multivariate Gaussian distribution
2. Perturb the model weights: `theta_wm = theta + xi` (add the key to the parameters)
3. Generate text using the perturbed model `p_theta_wm`
4. Return: generated text, the watermark key `xi`

Only ONE MLP layer's weights are perturbed. For Mistral-7B: layer 20, `up_proj` weight matrix (58M parameters). The layer is chosen empirically to balance detectability and quality.

### GaussMark.Detect (Watermark Detection)
1. Given: original model `p_theta`, prompt `x`, generated text `y`, watermark key `xi`, variance `sigma`
2. Compute the **test statistic**:
   `psi = <xi, grad_theta log p_theta(y|x)> / (sigma * ||grad_theta log p_theta(y|x)||)`
   where `<,>` is the dot product and `|| ||` is the L2 norm
3. Compute **p-value** = 1 - Phi(psi) where Phi is the standard normal CDF
4. If p-value < alpha (e.g., 0.05), reject the null hypothesis (claim: text is watermarked)

### Key Theoretical Results
- **Statistical Validity (Proposition 3.2)**: Under the null hypothesis H0 (text is NOT watermarked), `psi ~ N(0, 1)` exactly. This means p-values are uniformly distributed and the false-positive rate is exactly controlled.
- **Power Analysis (Proposition 3.4)**: Under a linear softmax model approximation, the test has non-trivial power that increases with model dimension and sequence length.

### Why It Works (Intuition)
- The watermark key `xi` is Gaussian and independent of the generated text under H0
- The gradient `grad_theta log p_theta(y|x)` is also independent of `xi` under H0
- Their dot product, normalized, follows a standard normal distribution
- Under H_A (text IS watermarked), the gradient is correlated with `xi`, making `psi` systematically large

### Practical Implementation
- Perturb only a single MLP layer (not the entire model) to minimize quality impact
- The gradient computation requires only ONE forward pass and ONE backward pass through the watermarked layer
- Generation: NO additional overhead (just weight perturbation, same as regular inference)
- Detection: <1 second for 1K tokens

### Rank-Reduced Variant (Section 4.4)
- Instead of perturbing all directions of a weight matrix, only perturb the **bottom k principal components**
- This allows MORE noise (stronger watermark) while preserving model quality
- Used in some experiments for better quality-watermark tradeoffs

# Evaluation

## Metrics

### Detection Metrics
- **Detection Rate at FPR=0.05**: Fraction of watermarked text samples detected when the false-positive rate is capped at 5%. This is the primary metric.
- **Detection Rate at FPR=0.01**: Same metric at a stricter 1% false-positive threshold.
- **Median p-value**: The median p-value across all samples. Lower values indicate stronger detection signals.
- **ROC AUC**: Area under the ROC curve, measuring overall discriminative ability.
- **p-value**: A statistical test p-value from the detection procedure. Values below 0.05 (or 0.01) indicate detection at that significance level.

### Quality Metrics
- **SuperGLUE Average**: Average accuracy across 8 language understanding tasks. Watermarked and unwatermarked models should have comparable scores.
- **GSM-8K Accuracy**: Accuracy on grade school math problems. Watermarked models should match unwatermarked.
- **AlpacaEval-2.0 Win Rate**: Preference win rate of watermarked vs. unwatermarked model. Should be near 50% (no preference).
- **Cross-entropy on C4**: Per-token cross-entropy on real text. Watermarked models should not differ significantly from unwatermarked.

### Robustness Metrics
- **Detection Rate after Corruption**: Detection rate after random insertions, deletions, or substitutions of tokens in the generated text.
- **AUC after Roundtrip Translation**: Detection AUC after translating text to another language and back.

## Baselines and Targets

### Paper's Reported Numbers (targets)
| Model | TPR@FPR=0.05 (200 tokens) | TPR@FPR=0.01 (200 tokens) | Median p-value (200 tokens) |
|-------|--------------------------|--------------------------|---------------------------|
| Mistral-7B | ~62% | ~40% | ~0.09 |
| Llama3.1-8B | ~95% | ~82% | ~0.008 |
| Phi3.5-Mini | ~65% | ~40% | ~0.08 |

### Quality Targets
Watermarked models should be within confidence intervals of unwatermarked models on SuperGLUE, GSM-8K, and AlpacaEval.

### Baseline (no watermark)
Unwatermarked text should have p-values uniformly distributed on [0, 1], giving ~5% detection at FPR=0.05 and ~1% at FPR=0.01.

## Evaluation Protocol

### Detection Evaluation
1. Take prompts from the C4 realnewslike dataset (first 1K samples, truncated at 200 tokens)
2. Generate text using the model (with and without watermark)
3. Run detection procedure on each generated sample
4. Compute detection rates at FPR=0.05 and FPR=0.01
5. Report median p-value across samples

### Quality Evaluation
1. Evaluate watermarked and unwatermarked models on SuperGLUE benchmark using lm-evaluation-harness
2. Evaluate on GSM-8K using chain-of-thought prompting
3. Run AlpacaEval-2.0 comparing watermarked vs unwatermarked

### Robustness Evaluation
1. Corrupt watermarked text (insertions, deletions, substitutions at various fractions)
2. Run detection on corrupted text
3. Report detection rate as function of corruption level
4. For semantic robustness, translate text through French and back, then detect

### Generation Settings
- Temperature: 1.0
- Top-p: 0.9 (or 1.0 for exact reproduction)
- Number of seeds: 3 (for variance estimation)
- Number of prompts: 100-1000
